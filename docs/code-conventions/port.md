# 포트 선언

> 포트 파일 하나가 어떤 구성을 갖고, 어떤 이름을 쓰는지.
>
> 포트와 어댑터가 무엇이고 어느 레이어가 소유하는지는 [레이어](../architectures/layering.md#포트와-어댑터)가 소유한다.

---

## 이름 규칙

| 대상 | 규칙 |
| --- | --- |
| 저장소 포트 파일 | 케밥 표기 + 저장소를 나타내는 접미사 |
| 그 밖의 포트 파일 | 케밥 표기 + 포트를 나타내는 접미사 |
| 계약 타입 | 파스칼 표기. 무엇을 해 주는지를 드러내고, 구현 기술은 담지 않는다 |
| 주입 토큰 | 계약 타입 이름을 스네이크 대문자로 옮긴 것 |

저장소 포트는 도메인 레이어의 정해진 폴더에 놓이고 모듈마다 하나씩 있으므로, 접미사가 저장소임을 가리킨다. 그 밖의 포트는 놓이는 자리가 정해져 있지 않아 접미사가 포트임을 가리킨다.

## 선언 형태

파일 하나가 **주입 토큰과 계약 타입 한 쌍**을 내보낸다.

```ts
export const <CONTRACT_NAME> = Symbol('<CONTRACT_NAME>');

/**
 * <이 계약이 무엇을 해 주는지>
 */
export abstract class <ContractName> {
    public abstract <operation>(...): Promise<...>;
}
```

토큰과 계약 타입은 **같은 파일**에 둔다. 참조하는 쪽이 배선과 타입을 위해 두 곳을 찾게 하지 않는다. 토큰 문자열은 이름과 같게 두어, 배선이 어긋났을 때 오류 메시지에서 어느 계약인지 읽힌다.

## 하지 말 것

- **계약 타입 이름에 구현 기술이나 저장 대상을 담기** — 포트는 안쪽의 언어로 적힌다. 기술이 이름에 들어가면 그것을 바꿀 때 이름이 먼저 낡는다.
- **모듈마다 같은 계약을 다시 선언하기** — 어느 것이 진짜인지 정할 수 없게 된다. 소유자를 정하는 기준은 [여러 모듈이 함께 쓰는 포트](../architectures/layering.md#여러-모듈이-함께-쓰는-포트)가 가진다.
