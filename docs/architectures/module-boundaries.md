# 모듈 경계

> 서비스 안을 어떤 단위로 나누고, 모듈이 서로에게 무엇을 공개하는지.

---

## 나누는 단위

서비스 안은 **기능 모듈**로 나눈다. 기본값은 애그리거트 루트 하나당 모듈 하나다.

다만 모듈과 애그리거트는 서로 다른 기준으로 그은 선이다. 애그리거트는 **일관성** 경계이고, 모듈은 **소유권과 결합** 경계다. 둘은 자주 겹치지만 같은 것은 아니므로, 정확한 관계는 다음과 같다.

```
모듈 하나 ⊇ 애그리거트 루트 하나 이상
```

## 절대 규칙

**애그리거트 루트와 그 자식 엔티티는 반드시 한 모듈 안에 있다.** 자식을 다른 모듈로 빼면 트랜잭션 경계가 모듈 경계를 가로지르게 되고, 모듈을 나눈 근거 자체가 무너진다.

반대로 루트가 여러 개인 모듈은 문제가 없다. 작은 루트가 생길 때마다 모듈을 늘리면 파편화만 남는다.

## 나눌지 합칠지 판단하기

새 애그리거트 루트는 **일단 기존 모듈에 넣는다.** 다음 신호가 보일 때 분리한다.

- 다른 모듈과의 응용 계층 호출이 계속 늘어난다
- 해당 개념을 다른 영역들이 함께 쓰기 시작한다
- 배포 주기나 담당이 갈린다

분리 순서는 항상 **모듈이 먼저, 서비스는 필요할 때**다. 모듈로 갈라두면 서비스로 승격하는 일은 경로 이동에 가깝지만, 그 반대는 어렵다.

## 공개 표면

모듈은 자신의 일부만 공개한다. 나머지는 다른 모듈이 볼 수 없다.

| 공개 | 이유 |
| --- | --- |
| 식별자 타입 | 모듈 간 참조의 유일한 수단 |
| 응용 계층 | 애그리거트 간 협력이 일어나는 자리 |
| 저장 모델 | 스키마 수준의 관계 선언에 필요 ([영속성 매핑](./persistence-mapping.md) 참고) |
| 모듈 정의 | 의존성 주입 배선 |

| 비공개 | 이유 |
| --- | --- |
| 애그리거트와 도메인 모델 | 다른 모듈이 남의 불변식을 직접 다루게 된다 |
| 저장소 구현과 매핑 | 교체 가능해야 할 세부 사항 |

이 경계는 린트로 강제한다. 규칙의 실제 내용은 린트 설정이 유일한 출처다.

## 모듈 간 참조

**도메인 계층끼리는 서로를 모른다.** 다른 모듈을 가리켜야 할 때는 식별자만 갖는다. 상대의 애그리거트를 직접 참조하지 않는다.

여러 애그리거트가 함께 있어야 성립하는 검증과 조율은 **응용 계층의 책임**이다. 애그리거트 하나가 혼자 지킬 수 없는 규칙은 애초에 그 애그리거트의 불변식이 아니다.

이때 공개하는 응용 계층 연산은 **애그리거트가 아니라 사실을 반환한다.** 애그리거트를 그대로 넘기면 응용 계층을 우회로 삼아 도메인 모델이 새어 나가므로, 경계를 둔 의미가 사라진다.

## 순환 금지

모듈 간 의존은 방향이 있는 비순환 그래프여야 한다. 순환이 생기면 그 둘은 사실 하나의 모듈이거나, 경계를 잘못 그은 것이다.
